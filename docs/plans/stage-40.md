# Этап 40. Свои шрифты и лёгкие картинки

Запрос Рустема (2026-10-09): из списка готовых решений взяты «шрифты оболочек через Fontsource» (п. 2) и «картинки городов и портреты» (п. 12). Оба — чисто технические, без новых решений по игре.

## Что сейчас
- Шрифты идут с Google Fonts из 19 мест: `web/index.html` (Lora, Poppins), `styles/shells/*.css` (13 оболочек, `@import`), движок тем (`cardTheme/index.ts` — три базовых и `requestFonts` по `FONT_SPEC` из `engine.mjs`, 34 семейства), наборы украшений (`cardTheme/packs.ts`, `ensurePackFont`), карта (`maps/fonts.ts`). Без сети оболочка и карта теряют шрифт, каждый игрок ходит к Google. Всего 45 семейств, все есть в Fontsource (`@fontsource/*` 5.3.0, шрифты OFL, пакеты MIT).
- Картинки сцен, противников и мест: `domain/media.ts` — sharp → один WebP до 1920 px. Карточка места, список противников и стол тянут полный файл; плейсхолдера нет; с телефона мастер отправляет исходник до 15 МБ (HEIC).

## Решения
- Шрифты — в сборку из `@fontsource/<семейство>`, по файлам подмножеств `cyrillic-<вес>.css` и `latin-<вес>.css` (курсив — где нужен). Внешних запросов за шрифтами не остаётся; `preconnect` к Google убирается.
- Один загрузчик `web/src/lib/fonts.ts`: `ensureFont(family)` — динамический импорт CSS нужного семейства, один раз. Движок тем, наборы и карта зовут его вместо `<link>` на Google. Базовые шрифты приложения (Lora, Poppins) и три базовых карточки — статически в `main.css`/движке.
- Оболочки: `@import` Google в `styles/shells/*.css` заменяется на `@import '@fontsource/...'` — Vite сам кладёт woff2 в сборку, чанк оболочки остаётся своим.
- PWA: woff2 из предкэша исключаются (иначе ~5 МБ при установке), вместо этого `runtimeCaching` CacheFirst `zg-fonts` для `/assets/*.woff2` — шрифт качается при первом показе, дальше без сети.
- Картинки: к полному файлу добавляется превью `<id>.t.webp` (до 480 px по длинной стороне) и `thumbhash` (пакет `thumbhash`, MIT; ~28 байт base64) — размытый плейсхолдер до загрузки. `ImageSchema` (игрок, стол, мастер) — `{url, thumb, hash, w, h}`, `strictObject`; хэш и превью уходят только вместе с url, то есть по тем же правилам видимости (`mediaAllowed` принимает и `<id>.t.webp`). Старые картинки без превью: превью и хэш считаются лениво при первом запросе мастера либо при `npm run media:rebuild`.
- Загрузка с телефона: перед отправкой `browser-image-compression` (MIT) уменьшает до 2048 px и ~2 МБ в браузере; HEIC остаётся как есть, если браузер его не декодирует (сервер умеет).
- Компонент `Pic` (`web/src/components/Pic.tsx`): рисует thumbhash как фон, затем превью или полный файл по размеру места; используется в карточке места, у противника, на столе и в списках мастера.

Не меняется: правила видимости картинок, пакеты тем и оболочек, 3D-карта.

## Шаги
1. **Шрифты.** Зависимости `@fontsource/*` (45), `web/src/lib/fonts.ts`, замена четырёх загрузчиков и 13 `@import`, `index.html` без Google, `vite.config.ts` (предкэш и `zg-fonts`). Запись в `docs/decisions.md`.
2. **Картинки.** Сервер: превью и thumbhash в `media.ts`, колонка `image_hash` в `scene`, `npc`, `map_place` (миграция 0014), `mediaAllowed`/`mediaPath` для превью, `ImageSchema` расширен, ленивый пересчёт для старых файлов. Веб: `Pic`, сжатие перед загрузкой в `GmNpcs`, `GmTable`, `GmPlaceCity`.
3. **Документы:** руководство (шрифты без сети; загрузка картинок с телефона), решения, ручные проверки `docs/test-cases/stage-40.md`, статус в плане.
