# Этап 41. Push-уведомления

Запрос Рустема (2026-10-09): из списка готовых решений — п. 1, push-уведомления игрокам (и мастеру). Цель: игроку не нужно держать приложение открытым, чтобы узнать, что мастер решил по предложению или ответил на запись; мастеру — что пришёл запрос. Подробностей не было; решения ниже приняты по умолчанию и записаны в `docs/decisions.md`.

## Решения
- **Web Push, библиотека `web-push`** (MIT) на сервере, протокол VAPID. Ключи — в env: `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (https-адрес, по умолчанию `PUBLIC_ORIGIN`; почта в subject не используется). Без ключей уведомления выключены: `/api/push/key` отвечает `{enabled: false}`, кнопки в интерфейсе нет. Ключи делает команда `npm run vapid:dev` / `vapid` (`server/src/cli/vapid.ts`): дописывает их в env-файл, если их там нет, и ничего не печатает, кроме «записано». Запускает Рустем.
- **Подписка = устройство.** Таблица `push_subscription`: id, room_id, member_id, endpoint (уникален), p256dh, auth, label (коротко: «iPhone», «Chrome на Mac»), created_at, last_ok_at, fails. Миграция 0015. Подписываются игрок и мастер; стол — никогда. Маршруты: `GET /api/push/key`, `POST /api/push/subscribe`, `POST /api/push/unsubscribe` (по endpoint своего участника). Подписки — внутренние данные сервера, наружу не уходят.
- **Тело уведомления — без свободного текста.** `PushNoteSchema` (strictObject) `{title, body, url, tag}`; в body только имена мест, разделов и персонажей, которые адресат и так видит; ни текста ответа мастера, ни текста слуха, ни заметок. Перед отправкой — `.parse()` и тот же предохранитель `findGmLeak`, что в `publish()` (единственное место отправки — `server/src/push/send.ts`). Push-службы Apple, Google и Mozilla получают тело зашифрованным (так устроен Web Push), но правило всё равно действует.
- **Когда шлём.** Игроку: мастер решил по его предложению («Идём в <место>» / «Предложение отклонено: <место>»); мастер ответил на запись дневника («Мастер ответил на запись»); в открытом городе открылся слух или задание («Новый слух в <город>»); мастер нажал «Позвать за стол» («Игра начинается»). Мастеру: новое предложение («<Имя> предлагает идти в <место>»), новый или изменённый «Вопрос мастеру» («Вопрос от <Имя>»). Личные записи («только для меня») уведомлений не порождают ни у кого.
- **Не дублировать открытое приложение.** Сервис-воркер перед показом смотрит, есть ли видимое окно приложения; если есть — уведомление не показывается (событие и так пришло по сокету). Нажатие по уведомлению открывает или фокусирует приложение на `url`.
- **Отказы.** Ответ 404/410 от push-службы — подписка удаляется; другие ошибки — `fails + 1`, после 5 подряд подписка удаляется. Отправка асинхронная, ошибки игру не останавливают (как у Jev).
- **Сервис-воркер остаётся сгенерированным** (`generateSW`), обработчики `push` и `notificationclick` — в `web/public/push-sw.js`, подключается через `workbox.importScripts`. Переход на `injectManifest` не нужен.
- **Значок на иконке** (Badging API): число непрочитанных вкладок игрока (`lib/unread.ts`) — на иконке установленного приложения; где API нет, ничего не происходит.
- **iOS:** уведомления работают только в установленном приложении (с 16.4). В неустановленном Safari кнопка подсказывает: «Добавьте на экран „Домой“».

Не меняется: сокет-события и `publish()`, видимость данных, Jev и Claude (уведомления к ним не ходят).

## Шаги
1. **Сервер.** Зависимости `web-push`, `@types/web-push`; `config.ts` — три ключа; `cli/vapid.ts` и скрипты `vapid`, `vapid:dev`; таблица `push_subscription`, миграция 0015; `shared/src/push.ts` — `PushNoteSchema`, `PushSubscribeSchema`; `server/src/push/send.ts` — `pushToMember`, `pushToGm`, предохранитель, обработка отказов; `routes/push.ts`; вызовы: `routes/maps.ts` (решение по предложению → автору; новое предложение → мастеру), `routes/gmScreen.ts` (ответ → игроку), `routes/playerDiary.ts` (запрос → мастеру), `routes/places.ts` (слух стал открытым в открытом месте → игрокам), `routes/gmSession.ts` — `POST /api/gm/session/call` «Позвать за стол» → всем игрокам.
2. **Веб.** `public/push-sw.js` + `importScripts` в `vite.config.ts`; `lib/push.ts` (поддержка, состояние, включить/выключить); `components/PushToggle.tsx` — колокольчик в шапке игрока и мастера (`RoleScreen actions`); значок на иконке из `unread.ts`; кнопка «Позвать за стол» на «Игре» у мастера.
3. **Документы:** руководство (игрок — как включить, что приходит, iOS; мастер — «Позвать за стол», уведомления о запросах; администрирование — `vapid`), решения, ручные проверки `docs/test-cases/stage-41.md`, статус в плане.
