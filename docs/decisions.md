# Решения

Формат: дата — решение — почему.

## 2026-10-05

- **Разработка на самом Mac mini, в `~/Desktop/Zelenogorie`.** Прод будет жить в `~/srv/zelenogorye/releases/<время>` с симлинком `current` (этап 1б, 7). Desktop для прода не годится из-за ограничений доступа macOS (TCC) для launchd.
- **Dev и прод разделены.** Dev: порт 3001, база `data/dev.sqlite`, env `~/.config/zelenogorye/.env.development`. Прод: порт 3000, env `~/.config/zelenogorye/.env`.
- **Node 24 из nvm** (`~/.nvm/versions/node/v24.13.1`), а не из Homebrew. В plist этапа 1б путь к node указывать абсолютный, из `which node`.
- **Сервер собирается esbuild в `server/dist`**, зависимости остаются внешними, `@zg/shared` вшивается. Dev — `tsx watch`.
- **Один BUILD_ID на сервер и клиент** (`scripts/build.mjs`). Клиент шлёт его в `sync:hello`; при несовпадении перезагружается один раз на версию.
- **Вход.** Приглашение гасится только POST-запросом по кнопке; GET безопасен для превью-ботов. Игрок задаёт 6-значный PIN при входе по приглашению. Вход по коду комнаты: выбор участника из списка (имена игроков и мастера видны тому, кто знает код комнаты; стол в списке не показывается) + PIN или пароль.
- **Rate limit.** 5 неудачных попыток за 15 минут на участника + 50 любых попыток за 15 минут на IP. В памяти процесса, после перезапуска сбрасывается. Следствие: кто знает код комнаты, может временно заблокировать вход конкретному игроку пятью неверными PIN — для домашней игры приемлемо.
- **Мастер входит паролем** (от 8 символов), он задаётся в `npm run setup`. У стола секрета нет: стол входит только по приглашению, мастер может выдать новую ссылку.
- **Предохранитель утечек** (`server/src/visibility/guard.ts`) блокирует ответ не-мастеру, если в нём маркер `СЕКРЕТ-МАСТЕРА` или ключи `gm_*`, `*_gm`, `gmXxx`, `xxxGm`. Следствие для кода: в DTO игрока и стола нельзя называть поля так, даже безобидные.
- **Jev.** SDK `@typesafe-ai/sdk` 0.6.0: параметры клиента `defaultModel` и `retry` (а не `model`/`retries`). Модель закреплена `jev-1.13.0`. `logLevel: 'warn'`, потому что `debug` печатает тела запросов с мастерскими текстами.
- **Мастерские тексты и черты уходят во внешний API TypeSafe** (как и в Claude API). Записи дневника «только для меня» не уходят никуда.
- **Определение зелёной магии для Jev** (`server/src/ai/jev/questions/greenMagic.ts`) взято из канона рандомизатора: чудеса, исполняющие желания (Lesser Miracle, Miracle, Divine Miracle), перегрузка — глаза и изумрудная кожа. Отсечение «мана, молитвы, способности родного мира — не зелёная магия» — моё прочтение канона, проверить. В песочнице определение можно править на лету.
- **Известное ограничение:** если дома пропал интернет, игра встаёт и для сидящих за столом — весь трафик идёт через Cloudflare.

## 2026-10-05, этап 2

- **Рандомизатор:** взята живая версия артефакта «Переход в Зеленогорье» с claude.ai (обновлена 2026-10-04), сохранена как `reference/randomizer-v5.17.html`. Внутри артефакта номер версии не записан (комментарии упоминают v5.10–v5.13).
- **Справочники остаются JSON-файлами в `seed/`**, а не таблицами в базе. Их делает `tools/extract-seed/extract.mjs`: куски данных выполняются в изолированном `vm`, строки попадают в JSON без изменений. Сервер читает их при старте и проверяет форму через Zod. Причина: движок работает с порядком строк как с частью логики (от него зависит выбор генератора), а таблицы в базе этот порядок не гарантируют.
- **`npm run seed` создаёт тестовых персонажей**, а не справочники.
- **Персонаж хранится как документ Char рандомизатора** в `character_secret.doc` (JSON) плюс строка `character` (комната, владелец, вид, имя, описание для игрока). Отдельной таблицы `trait_assignment` нет: слоты, ступени, раскрытие и история живут в документе, как в артефакте. Так импорт и экспорт JSON идут без потерь, а движок переносится без переписывания.
- **Движок перенесён построчно** (`server/src/domain/`): генератор (FNV-1a + mulberry32), индекс черт, бросок, сродство с профессией и архетипом, переброс, ручной выбор, доп. слоты, карточки, ступени, развилки, слои «Для мастера», уровень силы. Порядок вызовов генератора не менялся: тот же сид даёт того же персонажа.
- **Раскрытие** как в артефакте: `revealed = {trait, stages, price, hint}`. Добавлен режим «только подсказка»: черта не раскрыта, но подсказка задана — игрок видит текст подсказки без названия и категории. Уровни для мастера: скрыта / подсказка / раскрыта.
- **`projectForPlayer`** — перенос `toPublic` с белым списком полей и `PlayerCharacterSchema.parse` (strictObject на всех уровнях). Слоты без раскрытия и без подсказки не оставляют ничего. У слотов в ответе игроку нет идентификаторов.
- **Действия мастера с чертами** идут через Socket.IO (`gm:trait.setReveal`, `setStage`, `setTier`, `setFork`), остальное (бросок, сохранение, импорт, мета) — HTTP. Первая строка каждого `gm:*` — проверка роли.
- **У одного игрока — один персонаж.** Попытка отдать второго — ошибка `owner_taken`.
- **Местный персонаж** пока минимальный: имя, обращение, описание для игрока, заметки мастера, уровень силы. Что ещё нужно в его карточке — открытый вопрос.
- **Правило разницы сил в артефакте уже есть** (`powerCompare`): сравниваются ступени силы (Обычный, Героический, Монструозный, Легендарный, Полубог, Божественный), а не отношение чисел. Противник на две ступени выше — крит лишь царапает; на две ниже — критический урон без крита. Это расходится со стартовым предложением этапа 3 (отношение r). Решить до этапа 3.
- **Рекомендуемый уровень силы для ступеней** из артефакта: Освоение от 50, Мастерство от 100, Предел от 300. Показывается мастеру как подсказка, ничего не блокирует.

## 2026-10-05, этап 3

- **Правило разницы сил — из канона рандомизатора (`powerCompare`), не из стартового предложения плана.** Сравниваются ступени силы: Обычный 1–50, Героический 51–100, Монструозный 101–300, Легендарный 301–600, Полубог 601–1000, Божественный 1001+. Противник на 2+ ступени выше: любой успех d10 становится «Лишь царапина». На 2+ ступени ниже: успех → «Критический урон», провал → «Заметный урон». Разница в одну ступень — обычный бросок. T3.1 и T3.2 из плана этому правилу соответствуют. **Требует подтверждения Рустема** (`server/src/domain/rolls.ts`, одна функция).
- **Таблица d10** — стартовое предложение плана: 1 провал с осложнением, 2–5 провал, 6–8 успех, 9 сильный успех, 10 крит. d20 — бросок удачи без учёта силы.
- **Сила противника задаётся мастером на сессию** («Сессия» → «Противник»), а не в каждом броске. Игрокам ни имя, ни сила противника не уходят. Броски мастера идут без поправки на силу.
- **Лента: одна строка события на аудиторию** (`public`, `table`, `gm`, `member:<id>`) со своим `seq`. В строке лежит уже спроецированный DTO этой аудитории: игроку — публичный, мастеру — полный. Клиент хранит `lastSeq` по своим аудиториям; пропуск номера — сигнал досинхронизироваться (`sync:hello`). При сильном отставании или «будущем» номере (база восстановлена) приходит снимок последних 50 по всем аудиториям.
- **Дедупликация бросков** по `(member, clientRequestId)`: «Повторить» отправляет тот же id, двойное нажатие заблокировано на клиенте.
- **Все обработчики Socket.IO обёрнуты в try/catch** (`realtime/guarded.ts`): исключение — в лог и ответ `server_error`, процесс не падает. Повод: предохранитель утечек бросает исключение, и игрок мог бы уронить сервер, вписав маркер в текст броска. Такой текст теперь отклоняется на входе.
- **Jev в бросках (rollIntent, greenMagic) пока не подключён**: по плану — только после решения по итогам J0.

## 2026-10-05, этап 4

- **Экран мастера разбит на разделы:** «Игра» (противник, бросок, лента), «Партия» (персонажи, перегрузка), «Запросы» (дневники и вопросы игроков), «Заметки», «Участники» (приглашения, песочница Jev).
- **Перегрузка зелёной магией** — отдельная таблица `green_overload`: значение и пороги «глаза» (3) и «кожа» (6) на персонажа. Наружу уходит только по кнопке «Показать столу» и только видимый признак (`table:sign`), без числа.
- **Дневник:** три вида записи — обычная (видит мастер), «только для меня» (мастер не видит ни в UI, ни через API; фильтр в SQL-запросе, `diaryForGm` бросает исключение на личной записи), «вопрос мастеру» (не может быть личным, у мастера — со статусом «ждёт ответа / отвечен»).
- **Заметки сессии** — на текущую игровую сессию, автосохранение через 0,8 с после последней правки. Сохранение проверяет `updatedAt` версии, от которой шла правка: если в другой вкладке сохранили позже, мастер выбирает версию, ничего не затирается молча.
- **Jev подключён за флагами** `JEV_LEAK_GUARD`, `JEV_DIARY_MATCH`, `JEV_GREEN_MAGIC` (`rollIntent` пока нет). Пороги — стартовые, в `server/src/ai/jev/thresholds.ts`: страж 0,5 (чужая черта) и 3 из 4 (своя), дневник 2 из 3, зелёная магия 0,5. Уточнить по итогам J0. В проде флаги по умолчанию выключены (`config.ts`), в `.env.development` — включены.
- **Страж срабатывает до сохранения подсказки** (`/hint-check`), а не после: мастер видит предупреждение и решает сам. Если Jev не ответил — «проверка недоступна», сохранить можно.
- **Ответы Jev хранятся в `ai_judgment`** (мастерские данные). Подсказки «зелёная магия?» живут только в открытой вкладке мастера; после перезагрузки вкладки они пропадают (сырые ответы остаются в базе).

## 2026-10-05, этап 5

- **Сцена** — таблица `scene` (название, текст для стола, `text_gm`, картинка). Что показано на столе — `table_state`. Столу уходит только `projectForTable` (strictObject), `text_gm` не читается.
- **Картинки сцен** проходят через sharp: EXIF-поворот, не больше 1920 px по длинной стороне, WebP качества 80, метаданные выброшены. Лежат в `data/media/` (рядом с базой, вне релизов), имя файла случайное. Отдаются через `/api/media/…` с проверкой: мастеру — любая картинка его комнаты, столу — только картинка показанной сейчас сцены, игрокам — ничего. Кэш `private, immutable`: у каждой загрузки новое имя. Бэкап на этапе 7 должен забирать и `data/media/`.
- **Загрузка картинки** — сырым телом запроса с `Content-Type: image/*`, до 15 МБ, без multipart. HEIC зависит от сборки libvips в sharp; iPhone при выборе фото в браузере обычно отдаёт JPEG.
- **Стол** — отдельный полноэкранный экран без кнопки «Выйти»: сцена, последние 5 публичных бросков, плашки признаков перегрузки на 12 с. «Анимация выкл.» хранится на самом устройстве стола.
- **Страж Jev для текста сцены** проверяет по скрытым и намекнутым чертам всех персонажей комнаты (до 40 черт за запрос) перед «Показать на столе».

## 2026-10-05, этап 6

- **Сводки — перенос «SUMMARY» из рандомизатора:** три вида (для мастера, вступление для игрока, сцена перехода), промпты, пример, тоны и лица — дословно из `seed/summary-*.json`. Данные: мастеру — всё, включая заметки (урезка до 12 000 символов как в артефакте); вступлению — только `projectForPlayer` в форме `toPublic`, без подсказок к нераскрытым чертам; сцене перехода — происхождение и «признаки до раскрытия» скрытых черт.
- **Модели:** «Написать» — `claude-sonnet-5-5` (effort `medium`, мышление адаптивное по умолчанию, серверный запасной вариант при отказе — `fallbacks: 'default'`), «Быстрый черновик» — `claude-haiku-4-5`. Обе задаются в `.env`. Prompt caching не включён: сводок за сессию единицы, а общий префикс промпта (≈1,5 тыс. токенов) у трёх видов разный, выигрыш копеечный.
- **Новый текст всегда неопубликован.** Опубликовать игроку можно только вступление и сцену перехода; перед публикацией Jev проверяет выдумки относительно данных (`FACT_WARN = 0,6`) и утечку скрытых черт персонажа. Если Jev не ответил — мастер видит это и решает сам.
- **Ошибки Claude** (нет ключа, ключ не принят, лимит, таймаут, нет сети, отказ модели) возвращаются мастеру понятным текстом; сервер и игра продолжают работать.

## 2026-10-05, этапы 1б и 7

- **Службы — LaunchDaemon в `/Library/LaunchDaemons` с `UserName` владельца** (сервер, nginx, бэкапы, IP Cloudflare, DDNS, ротация логов). Стартуют без входа в систему. FileVault нужно выключить (docs/ops.md).
- **Перезапуск при выкладке без sudo:** `deploy.sh` шлёт серверу SIGTERM, launchd (KeepAlive) поднимает его из нового `current`. `launchctl kickstart` в системном домене требует root, поэтому не используется. sudo нужен только для установки служб и для `restore.sh`.
- **Релизы:** `deploy.sh` клонирует закоммиченный код из рабочего репозитория (`file://`), так что в прод попадает только то, что в git. Ссылка `current` меняется атомарно (`mv -h`), хранятся 3 релиза.
- **Защита origin:** `ssl_reject_handshake` для любого чужого имени, Authenticated Origin Pulls (глобальный CA Cloudflare; при желании позже — свой сертификат на зону), allow только IP Cloudflare, `real_ip_header CF-Connecting-IP`. Конфиг проверен `nginx -t` на nginx 1.29.5 с временным сертификатом.
- **Бэкапы:** `backup.mjs` — SQLite backup API, `integrity_check`, gzip, копия `data/media`; каждые 30 минут при игре за последние 3 часа и ежедневно в 04:00; 48 + 30 снимков; зеркало `BACKUP_MIRROR` необязательное, его ошибка не ломает основной снимок.
- **Логи:** копия с датой и обнуление на месте раз в сутки (launchd открывает логи с дозаписью, переоткрывать не нужно), архивы 14 дней. Без newsyslog и root.
- **Страница «Состояние»** у мастера в «Участниках»: версия, аптайм, память, размер базы и картинок, последний бэкап, `nginx -t` (если задан `NGINX_BIN`), дата списков Cloudflare, DDNS, наличие ключей.

## 2026-10-05, оформление и правки после первого запуска

- **Оформление в стиле Claude** (Anthropic brand guidelines): кремовый `#faf9f5` / почти чёрный `#141413`, оранжевый акцент `#d97757`, Poppins для интерфейса и заголовков, Lora для текста карточек, дневника, заметок и сводок. Тёмная тема — по системной настройке. Общий экран всегда тёмный. Иконка перекрашена. Шрифты — Google Fonts.
- **Socket.IO: отсутствие `Origin` разрешено.** Браузер не шлёт Origin в GET на свой же сайт, и первый запрос polling отклонялся — индикатор висел на «Переподключение». Межсайтовые запросы Origin несут всегда; вход всё равно по cookie.
- **Список входа по коду комнаты** показывает только тех, кто уже задал PIN или пароль.
- **`npm run setup` без терминала:** пароль мастера из `ZG_GM_PASSWORD`. Корневые `*:dev` скрипты передают аргументы дальше (`-- --name …`).
- Блок «Сводки» на странице персонажа свёрнут по умолчанию.

## 2026-10-05, этап 8

- **Дальнейшие этапы 8–11** (решение Рустема): сначала готовность к первой сессии, потом библиотека противников, дополнения карточки, удобства игрока. Снаряжение правят игрок и мастер, состояния и связи — только мастер. Уведомления — значки внутри приложения, без Web Push (новая зависимость, VAPID-ключи, свой service worker, на iOS только в установленном приложении 16.4+).
- **Заметки привязаны к сессии и на сохранении.** Клиент шлёт `sessionId`; если мастер в другой вкладке начал новую сессию, сервер отвечает 409 `session_changed`, и мастер сам решает, переносить ли текст. Без этого несохранённый текст старой сессии молча попадал бы в новую.
- **Суждения Jev о записи дневника стираются**, когда запись становится личной или удаляется (`forgetJudgments`). Фоновая проверка `diaryMatch` после ответа Jev перечитывает запись: если она стала личной, удалена или переписана, ответ выбрасывается. Раньше в этом окне мастеру уходила устаревшая копия текста записи, уже ставшей личной (нарушение правила 7 CLAUDE.md).
- **Вопрос с ответом мастера остаётся вопросом** при правке игроком: меняется только текст.

## 2026-10-05, этап 9

- **Противник сессии копируется из библиотеки** (имя и сила в строку `game_session`) плюс ссылка `opponent_npc_id`. Броски по-прежнему читают только строку сессии. Правка силы противника из библиотеки обновляет копию в сессии, удаление противника оставляет копию как ручной ввод.
- **Миграция 0005_npc поправлена руками:** drizzle-kit при `ADD COLUMN` с внешним ключом не пишет `ON DELETE SET NULL`, и удаление противника падало бы на внешнем ключе. В схеме Drizzle правило указано; при следующих `db:generate` это место проверять.
- **Конвейер картинок вынесен в `domain/media.ts`** (`storeImage`, `removeImage`, `mediaAllowed`, `mediaPath`). Стол получает портрет только показанного противника, как и картинку только показанной сцены.
