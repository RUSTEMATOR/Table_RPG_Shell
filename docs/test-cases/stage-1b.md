# Этап 1б — ручные проверки (после docs/ops.md, шаги 1–4)

| № | Шаги | Ожидание |
|---|---|---|
| T1.1 | Телефон, Wi-Fi выключен → `https://zg.<домен>`. | Открывается, замок в адресной строке, сертификат Cloudflare. |
| T1.2 | С мобильной сети `https://<внешний IP>`. С другого устройства в домашней сети `http://<IP мака>:3000` и `https://<IP мака>:8443`. | Обрыв TLS или 403; порт 3000 не отвечает; 8443 без Cloudflare — обрыв (нет клиентского сертификата). |
| T1.3 | Установка PWA: iOS «На экран Домой», Android «Установить». | Открывается без адресной строки, иконка гора на тёмном фоне. |
| T1.3а | iOS: войти в Safari → установить PWA → открыть PWA. | Если сессии нет — вход по коду и PIN работает. |
| T1.4 | iOS 18.4+: установленная PWA, 10 минут без касаний. | Экран не гаснет. |
| T1.5 | `pkill -9 -f "server/dist/index.mjs"`, засечь время. | `curl 127.0.0.1:3000/api/healthz` отвечает через ≤15 с. |
| T1.6 | Перезагрузить Mac и в систему не входить. С телефона открыть сайт. | Сайт работает. |
| T1.6а | Выдернуть питание Mac mini на 10 с, включить, не входить в систему. | Через пару минут сайт работает. |
| T1.10 | Открыть экран игрока и не трогать 30 минут. `grep -c " 499 \| 504 " ~/srv/zelenogorye/logs/nginx-access.log`. | Индикатор зелёный всё время, 499/504 нет. |
| T1.12 | Зайти с телефона, посмотреть последнюю строку `nginx-access.log`. | В начале строки IP телефона (оператора), а не Cloudflare. |
| T1.14 | `curl -k --resolve other.example:443:<внешний IP> https://other.example` с мобильного хотспота. | Соединение закрывается сразу. |
| T1.15 | `bash ops/scripts/update-cf-ips.sh`. | «Списки Cloudflare обновлены», сайт работает. |
| T1.16 | (Если DDNS) В Cloudflare вручную поменять A-запись на 1.2.3.4, подождать 5 минут. | Запись вернулась на настоящий IP, в `logs/ops.log` строка «DDNS: … → …». |
