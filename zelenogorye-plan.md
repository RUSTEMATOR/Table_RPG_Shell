# Платформа «Зеленогорье» — план для Claude Code

## Context

Рустем ведёт свою НРИ «Зеленогорье» для группы из 3–4 человек: смешанный состав (попаданцы и местные), гибридный формат (часть за столом, часть онлайн), сессии по 5+ часов, игроки сидят с телефонов. Сейчас есть только рандомайзер черт попаданцев — HTML-артефакт v5.17 на claude.ai. Нужен свой веб-сервис для проведения сессий:
1. карточка персонажа и личный дневник игрока;
2. броски d10/d20 с учётом разницы уровней силы и общая лента;
3. экран мастера;
4. общий экран для ТВ и стрима в Discord.

Решения уже приняты:
- хостинг на Mac mini M4 в квартире на Отрадном;
- без туннелей и VPN: домен в Cloudflare (проксируемая A-запись), проброс порта на роутере, nginx перед Node;
- ИИ: Claude API генерирует тексты, TypeSafe Jev выносит быстрые типизированные суждения (см. раздел «Jev»).

Срока нет. Проект пишется с нуля, существующего кода нет.

Правила работы:
- сначала план, потом исполнение;
- план пишет сильная модель, код — исполнитель, механику — Haiku;
- тесты не пишем и не запускаем, ни автотесты, ни скрипты-проверялки, токены на прогоны не тратим: каждый этап заканчивается ручными тест-кейсами, Рустем проверяет всё руками;
- единственный служебный скрипт — `tools/extract-seed/`: это перенос данных, а не проверка;
- субагентов запускаем только когда без них не обойтись;
- без эмодзи.

## Архитектура

```
Телефон / ТВ / ноутбук
  → https://zg.<домен> (Cloudflare proxy, SSL Full strict, Authenticated Origin Pulls)
  → роутер: внешний 443 → MacMini:8443
  → nginx (TLS origin-cert, mTLS от Cloudflare, allow только IP Cloudflare, статика, proxy)
  → 127.0.0.1:3000 Node (Fastify + Socket.IO) → SQLite (WAL)
                                              → Claude API, TypeSafe API (только с сервера)
```

| Слой | Выбор |
|---|---|
| Рантайм | Node.js 24 LTS, TypeScript strict, npm workspaces `server` / `web` / `shared` |
| HTTP | Fastify 5, слушает только `127.0.0.1:3000` (dev — `3001`), `trustProxy: '127.0.0.1'` |
| Realtime | Socket.IO 4, ресинхронизация по `seq` своей аудитории |
| БД | SQLite WAL, better-sqlite3 + Drizzle (drizzle-kit migrate) |
| Валидация | Zod 4 в `shared/`, выходные DTO — `z.strictObject()` на всех уровнях вложенности |
| Клиент | React 19 + Vite + vite-plugin-pwa (`registerType: 'autoUpdate'`), mobile-first |
| Фронт-сервер | nginx (Homebrew) на 8443 |
| Процессы | LaunchDaemon `com.zelenogorye.server` и `com.zelenogorye.nginx` с `UserName=rustem`, `KeepAlive`, логи в `logs/` (см. этап 0, п. 6) |
| ИИ | `@anthropic-ai/sdk` для генерации текста, `@typesafe-ai/sdk` (Jev) для суждений. Оба только на сервере, модели задаются в `.env` |

## Главный инвариант: данные мастера не уходят игроку

- Секреты лежат в отдельных таблицах: `character_secret`, `green_overload`, `session_note`, `ai_judgment`, а также в полях `gm_*` и `*_gm`.
- Игроку и столу данные отдаются только через `server/src/visibility/` (`projectForGm`, `projectForPlayer(memberId)`, `projectForTable`) по белому списку полей и с проверкой `z.strictObject(...).parse()` на всех уровнях вложенности.
- Все события уходят через одну функцию `server/src/realtime/publish.ts`. Прямые `socket.emit` и `io.emit` запрещены.
- Runtime-предохранитель: `publish()` и `onSend`-хук Fastify для ролей player и table проверяют сериализованный payload на маркер `СЕКРЕТ-МАСТЕРА` и на ключи `gm_*` и `*_gm`. В dev — исключение, в проде — не отправлять и писать в лог.
- Каждый обработчик `gm:*` первой строкой проверяет, что `role === 'gm'`.
- Скрытые черты не выдают даже своё количество. Поэтому:
  - `seq` событий ведётся отдельно для каждой аудитории (публичная, стол, каждый игрок, мастер), чтобы у игрока не было пропусков;
  - всё, что уходит игроку и столу, адресуется случайными id (nanoid), а не автоинкрементом;
  - порядок черт в карточке не оставляет «дырок».
- Записи дневника «только для меня» не видит мастер и не уходят ни в Jev, ни в Claude.
- Результаты Jev — мастерские данные и уходят только в аудиторию `gm`.
- Во всех мастерских полях тестовых персонажей стоит маркер `СЕКРЕТ-МАСТЕРА`. Если он попал в ответ игроку или столу, это блокирующий дефект.

- `.env` — ключ Claude API, `JEV_API_KEY`, секрет сессий, токен Cloudflare API (только `Zone.DNS:Edit` на одну зону);
- `.env.development` — то же для dev, отдельная база;

Сейчас ключ Jev лежит в `~/Desktop/Zelenogorie/.env` с правами 644. На этапе 1а его нужно перенести.

Прод живёт в `~/srv/zelenogorye/releases/<время>/`, на текущий релиз указывает симлинк `current`. Каталог `data/` (база, бэкапы) и `logs/` лежат рядом, вне релизов.

## Этапы

Роли: [П] планировщик (`claude --model opusplan`, plan mode), [И] исполнитель (Sonnet, новая сессия на каждый шаг), [Х] Haiku (механические задачи без влияния на безопасность), [Р] Рустем (руками на Mac и роутере).

Порядок: этап 0 ведётся параллельно с кодом. Этапы 1а, J0, 2 и 3 ведутся локально и не ждут этапа 0. Этап 1б начинается после T0.1.

### Этап 0. Инфраструктура на Отрадном ([Р], до этапа 1б)
1. Проверить, белый ли IP. WAN-адрес на Huawei должен совпадать с тем, что показывает 2ip.ua. Если это CGNAT (адреса 100.64–127.x, 10.x и т.п.), проброс снаружи не заработает: остановиться и решить с провайдером.
2. Узнать у провайдера, статический ли адрес. Если нет — на этапе 1б нужен `update-dns.sh` (DDNS через Cloudflare API).
3. Проверить двойной NAT: посмотреть WAN-адрес TP-Link. Схема по приоритету:
   - (а) Huawei в режиме моста;
   - (б) Mac mini кабелем прямо в Huawei и проброс только там;
   - (в) проброс на Huawei → TP-Link → Mac.

   Точные шаги зависят от модели Huawei, их нужно уточнить.
4. DHCP-резервация IP для Mac mini, подключение по кабелю.
5. Проброс: внешний TCP 443 → Mac:8443. Если провайдер режет входящий 443: Cloudflare ходит к origin и на порты 2053, 2083, 2087, 2096, 8443, а Origin Rules на бесплатном тарифе меняют порт.
6. Автозапуск без входа в систему. LaunchAgent и `brew services` без sudo стартуют только после входа пользователя, а с FileVault Mac после сбоя питания ждёт пароль ещё до загрузки системы. Рекомендуемая схема:
   - FileVault выключен;
   - сервер и nginx — LaunchDaemon в `/Library/LaunchDaemons` с `UserName=rustem` (sudo нужен один раз при установке).

   Запасная схема: FileVault выключен, автовход включён, остаются LaunchAgent. Она проще, но любой, кто сел за Mac, сразу оказывается внутри.
7. Mac:
   - `sudo pmset -a sleep 0 disksleep 0 autorestart 1`;
   - отключить автоустановку обновлений macOS с перезагрузкой;
   - если в районе бывают отключения света — ИБП на Mac mini и роутеры.
8. Купить домен в Cloudflare. Создать проксируемую A-запись `zg.<домен>` на внешний IP. Настройки:
   - SSL/TLS: Full (strict), Always Use HTTPS, WebSockets включены, Bot Fight Mode выключен;
   - Authenticated Origin Pulls с сертификатом на уровне зоны;
   - выпустить Origin Certificate на 15 лет и положить его в `~/.config/zelenogorye/tls/`.
9. Установить `brew install node@24 nginx`. `node@24` — keg-only, путь к нему `/opt/homebrew/opt/node@24/bin/node`; записать его и `which nginx`. Проект положить в `~/srv/zelenogorye`, не в Documents или Desktop.
10. Ключ Claude API и месячный лимит расходов в Console. Ключ Jev уже есть.

Тест-кейсы:
- T0.1 `nginx` с тестовой страницей на 8443 открывается с телефона по мобильной сети через `https://zg.<домен>`.
- T0.2 Прямой заход на `https://<внешний IP>` с мобильной сети не открывает страницу (после этапа 1б — 403 или обрыв).

### Этап J0. Песочница Jev и ручная проверка на русском (после этапа 1а)
Цель: до встраивания Jev в игровые экраны Рустем руками проверяет, какие функции работают на русских текстах Зеленогорья, и выбирает стартовые пороги. Документация TypeSafe прямо требует проверки на своих данных: английский у Jev основной, остальные языки работают хуже.

1. [П] Вопросы (`noul` / `choice` / `score`, инструкции и критерии) для четырёх функций из раздела «Jev», сразу в виде файлов `server/src/ai/jev/questions/*.ts`.
2. [И] Мастерская страница `/gm/jev`: выбрать функцию и черту, вставить текст, нажать «Спросить» → ответы, вероятности и уверенность. Каждый запрос — только по нажатию, без пакетных прогонов. Это часть продукта: позже мастер будет на ней настраивать пороги.
3. [Р] Руками прогнать свои примеры:
   - настоящие черты с подсказками, которые выдают и не выдают черту;
   - придуманные записи дневника;
   - заявки действий, в том числе с зелёной магией.
4. [П] + [Р] По каждой функции решение: берём / дорабатываем вопросы / отказываемся. Решения и пороги записать в `docs/decisions.md`.

Тест-кейсы:
- TJ.1 `/gm/jev` без cookie мастера → редирект на вход; игрок получает `error:forbidden`.
- TJ.2 Неверный `JEV_API_KEY` → на странице понятная ошибка, сервер жив, значения ключа нет ни в ответе, ни в логе.
- TJ.3 Для каждой выбранной функции в `decisions.md` выписаны порог и найденные ошибки с примерами.

### Этап 1а. Каркас, вход (локально)
Цель: пустое приложение работает на localhost и в локальной сети, вход по приглашению и PIN работает, WebSocket держится.

1. [П] Написать `docs/plans/stage-1a.md`, `CLAUDE.md` (текст ниже), `docs/decisions.md`. Решить, где идёт разработка (на Mac mini или другой машине) и где живёт git-репозиторий, из которого берёт код `deploy.sh`.
2. [Р] `git init`. Перенести `.env` в `~/.config/zelenogorye/`, `chmod 600`. Экспортировать рандомайзер с claude.ai в `reference/randomizer-v5.17.html`.
3. [И] Workspaces, TS strict, скрипты `dev`, `build`, `typecheck`, `db:generate`, `db:migrate`. Dev и прод разделены: порт 3001 против 3000, отдельная база, `.env.development`.
4. [И] Fastify:
   - `GET /api/healthz`, слушает только `127.0.0.1`;
   - `Cache-Control: no-store` для `/api/`;
   - `onSend`-предохранитель из инварианта.

   Статику в проде отдаёт nginx.
5. [И] Socket.IO на `/socket.io/`, проверка `Origin` в `allowRequest`, индикатор соединения в клиенте. Клиент шлёт версию сборки в `sync:hello`; при несовпадении сервер просит перезагрузку.
6. [И] SQLite: WAL, `foreign_keys=ON`, `busy_timeout=5000`. Таблицы `room`, `member` (роль gm/player/table, `pin_hash`, `invite_token_hash`), `auth_session`. Наружу — только nanoid-идентификаторы.
7. [И] Вход:
   - `npm run setup` создаёт комнату и пароль мастера (argon2id);
   - игроку выдаётся одноразовая ссылка-приглашение `/join/<token>` на 7 дней, в базе хранится только хэш;
   - `GET /join/<token>` только показывает страницу «Войти как <имя>» и токен не гасит, потому что превью-боты Telegram, Discord и iMessage сами открывают ссылку;

   - после входа ставится cookie `HttpOnly; Secure; SameSite=Lax` на 180 дней;

Игроки за столом и игроки одного мобильного оператора делят внешний IP, поэтому лимит только по IP заблокировал бы всех.
8. [И] PWA: manifest (`display: standalone`), service worker кэширует только оболочку, `registerType: 'autoUpdate'`. `wakeLock.ts` повторно запрашивает блокировку экрана на `visibilitychange`.
9. [И] `server/src/ai/jev/client.ts`:
   - `new TypeSafeClient({ apiKey: env.JEV_API_KEY, model: env.JEV_MODEL })`, `JEV_MODEL=jev-1.13.0`;
   - таймаут 3 с, одна повторная попытка;
   - SDK по умолчанию читает `TYPESAFE_API_KEY`, поэтому ключ передаётся явно.

Готово, когда: мастер и игрок входят с телефона в локальной сети по dev-адресу, typecheck чистый.

### Этап 1б. nginx, автозапуск, внешний доступ (после T0.1)
Цель: приложение открывается с телефона по домену, всё переживает перезагрузку и сбой питания без входа в систему.

1. [П] `docs/plans/stage-1b.md`.
2. [И] `ops/nginx/zelenogorye.conf` (это граница безопасности, поэтому не Haiku):
   - `listen 8443 ssl`, http2, origin-сертификат, TLS 1.2+;
   - `server_name zg.<домен>`; отдельный `default_server` с `return 444`, чтобы не отвечать чужим зонам Cloudflare, направленным на наш IP;
   - `ssl_verify_client on` с CA Authenticated Origin Pulls;
   - `include cloudflare-ips.conf` (`allow` по диапазонам) и `deny all`;
   - `set_real_ip_from` для тех же диапазонов, `real_ip_header CF-Connecting-IP`;
   - `root ~/srv/zelenogorye/current/web/dist`: хэшированные ассеты кэшируются на год, `index.html` и `sw.js` — `no-cache`, SPA-fallback на `index.html`;
   - `location /api/` и `location /socket.io/` проксируются на `127.0.0.1:3000`, с `Upgrade`/`Connection` для WebSocket и `proxy_read_timeout 3600s`;
   - `client_max_body_size 15m`; мягкий `limit_req` на `/api/auth/` (основной лимит — в приложении).
3. [Х] `update-cf-ips.sh`: раз в неделю скачивает `https://www.cloudflare.com/ips-v4` и `ips-v6`, пересобирает `cloudflare-ips.conf`, делает `nginx -t && nginx -s reload`. Запускается через `com.zelenogorye.cfips.plist`.
4. [Х] `update-dns.sh` + `com.zelenogorye.ddns.plist` (только если адрес не статический): раз в 5 минут сверяет внешний IP с A-записью и обновляет её через Cloudflare API.
5. [Х] `com.zelenogorye.server.plist` и `com.zelenogorye.nginx.plist` — LaunchDaemon:
   - `UserName=rustem`, абсолютный путь к node (`/opt/homebrew/opt/node@24/bin/node`), `WorkingDirectory` на `current`, `EnvironmentVariables` (путь к `.env`);
   - `RunAtLoad`, `KeepAlive`, `ThrottleInterval` 10;
   - stdout и stderr в `logs/`.
6. [Х] `status.sh`:
   - `launchctl print system/com.zelenogorye.server`;
   - `curl 127.0.0.1:3000/api/healthz`;
   - `nginx -t`;
   - проверка, что ключи Claude и Jev заданы (без вывода значений).
7. [Р] `sudo launchctl bootstrap system /Library/LaunchDaemons/…` для сервера и nginx.

Готово, когда: мастер и игрок входят с телефона по мобильной сети, после перезагрузки Mac всё поднимается само без входа в систему.

## Jev

TypeSafe Jev — модель System One. На вход она получает состояние (state) и типизированные вопросы, на выход возвращает:
- `choice` — выбор одного варианта с вероятностями;
- `noul` — вероятность «да» от 0 до 1;
- `score` — оценку по описанным уровням (от 2 до 10 уровней);
- плюс `confidence`.

Источник — docs.typesafe.ai, проверено 2026-10-05.

### Границы
- Текст Jev не генерирует. Он не замена Claude ни для сводок, ни для исполнителя кода.
- Не считает и не сравнивает числа надёжно. Разница сил, пороги перегрузки, рандомайзер и вселенные остаются в коде.
- Русский поддерживается хуже английского, поэтому до встраивания нужен этап J0.
- Модель `jev-1.13.0`, контекст 64k (из них 32k на state и самый длинный вопрос). Ввод — $0,042 за миллион токенов, вывод бесплатный.
- Слабые места: склонность к первому варианту в Choice, точность падает от лишнего контекста, вопросы понимаются буквально. Отсюда правила: в state только нужное, порядок вариантов нейтральный, всегда есть вариант «ничего не подходит».
- JS SDK `@typesafe-ai/sdk` (Node 20+): `new TypeSafeClient({ apiKey, model, timeout, retries })`, `client.systemOne({ state, questions })`, помощники `choice`, `noul`, `score`. Ошибки `AuthenticationError`, `RateLimitError`, `APITimeoutError` и другие. HTTP: `POST https://api.typesafe.ai/v1/systemone`.

### Функции по приоритету
Общее правило: Jev только советует мастеру. Он ничего не меняет в состоянии игры сам и никогда не отвечает игроку или столу.

1. **Семантический страж утечек** (`leakGuard`, этапы 4–6). Маркер ловит копирование секрета, но не пересказ. Перед публикацией текста, написанного мастером или Claude, сервер спрашивает Jev по каждой скрытой и намекнутой черте персонажа.
   - `noul`: «текст называет черту, описывает её действие или однозначно на неё указывает».
   - Для hinted-черт — `score` от 0 до 4: насколько подсказка раскрывает черту.
   - Мастер видит предупреждение и может всё равно опубликовать. Блоком остаётся только маркер.
   - Для сводок — ещё `noul` на каждое утверждение: «подтверждается данными персонажа».
2. **Дневник → подсказки для раскрытия** (`diaryMatch`, этап 4). При сохранении записи, кроме записей «только для меня», считается `score` 0–3 на каждую скрытую черту: «запись описывает проявление этой черты». Мастер видит «игрок, похоже, нащупал черту X» со ссылкой на запись.
3. **Заявка действия → предложение броска** (`rollIntent`, этап 3, по желанию).
   - `choice` вида броска: `d10`, `d20`, «бросок не нужен», «неясно».
   - `choice` подходящей раскрытой черты, с вариантом «ни одна».
   - При низкой уверенности подсказки нет.
4. **Зелёная магия → +1 к перегрузке** (`greenMagic`, этап 4, по желанию). `noul`: «в описании действия персонаж применяет зелёную магию». Счётчик меняет только мастер.

### Устройство
- `server/src/ai/jev/client.ts` — единственная точка вызова. Подробности — этап 1а, п. 9.
- `server/src/ai/jev/questions/`: `leakGuard.ts`, `diaryMatch.ts`, `rollIntent.ts`, `greenMagic.ts`. Каждый файл собирает минимальный state и вопросы и возвращает типизированный результат. Пороги лежат в коде; стартовые значения берутся из `docs/decisions.md` после J0.
- Независимые вопросы по одному state идут одним запросом. Для стража — один текст и по вопросу на черту со ссылкой на `traits.<id>`. Если J0 покажет, что соседние черты мешают, — по запросу на черту.
- Таблица `ai_judgment` (вид, ссылка на объект, модель, сырые ответы, время) нужна для настройки порогов. Это мастерские данные; результаты уходят только через `publish()` в аудиторию `gm`.
- Отказ Jev (нет сети, 429, таймаут) игру не останавливает: подсказки просто не появляются. У стража мастер видит «проверка недоступна».
- Флаги `JEV_LEAK_GUARD`, `JEV_DIARY_MATCH`, `JEV_ROLL_INTENT`, `JEV_GREEN_MAGIC` в `.env`.
- В `decisions.md`: мастерские тексты и черты уходят во внешний API TypeSafe, как и в Claude API; записи «только для меня» не уходят никуда.
